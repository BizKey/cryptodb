# cryptodb

Будущий репозиторий для базы данных **PostgreSQL** проекта *cryptodb*.

> **Статус:** начальный скелет (scaffold). Стек приложения и инструмент миграций пока не определены. Репозиторий проектируется как «чистая» БД: схема + миграции, без прикладного кода.

## Цель

Собрать в одном месте:

- **эволюционные миграции** БД (изменения схемы во времени);
- **итоговую схему** базы данных (reference-вид после стабилизации);
- документацию и соглашения по разработке схемы.

## Структура репозитория

```
cryptodb/
├── .editorconfig         # единые настройки редактора
├── .env.example          # шаблон переменных окружения для подключения
├── .gitignore
├── README.md
└── db/
    ├── migrations/       # SQL-миграции: V001__init.sql, V002__…, …
    └── schema/           # итоговая (целевая) схема: DDL / описание объектов
```

## Локальный запуск PostgreSQL

Для разработки потребуется работающий экземпляр PostgreSQL 15+:

```bash
# скопировать шаблон и заполнить значения
cp .env.example .env

# пример: подгрузить переменные и подключиться
set -a; source .env; set +a
psql -h "$PGHOST" -p "$PGPORT" -U "$PGUSER" -d "$PGDATABASE"
```

> Вариант с Docker (docker-compose) появится позже, когда определимся с окружением.

## Миграции

- Инструмент миграций (Flyway / Liquibase / goose / golang-migrate и т. п.) ещё **не выбран**.
- Файлы размещаются в `db/migrations/` и именуются по схеме `V<номер>__<описание>.sql`:

  ```
  V001__init.sql
  V002__add_users.sql
  V003__create_crypto_prices.sql
  ```

- Номер версии уникален и не меняется после применения; уже применённую миграцию не редактируем — только новая миграция.

Подробности — в [`db/migrations/README.md`](db/migrations/README.md).

## Переменные окружения

Параметры подключения к PostgreSQL описаны в [`.env.example`](.env.example).
Файл `.env` (с реальными значениями) в git **не** коммитится.
